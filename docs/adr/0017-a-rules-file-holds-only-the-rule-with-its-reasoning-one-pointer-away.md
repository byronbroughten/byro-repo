# A rules file holds only the rule, with its reasoning one pointer away

The style doc is opened for every TypeScript edit, so its worked examples were paid on every turn that only needed the rule, and once it became one line per rule it was followed more consistently. So every rules file holds bolded one-line rules, a "When | File" table into its reasoning folder, and the fixed sentence saying when to open a reasoning file; examples, instances, citations and reasoning sit in that folder and are never auto-loaded. A rule line is the rule plus at most a clause of scope or its one exception, and that written convention, held by review, replaced a 300-character lint cap on rule lines.

Source: byronbroughten/byro-repo#108, byronbroughten/byro-repo#110, a7810dd

## Considered Options

- **Keep the worked examples beside each rule.** Rejected: the required read paid for them on every edit that needed only the rule.
- **Cap rule lines at 300 characters.** Tried and dropped: the cap became a target, and rules clustered just under it, padded with an example or a second clause or squeezed to fit, so it bought neither brevity nor clarity. A number can measure only one of the two.
