# An observation index is the observation's home and records only what was seen

An observation index (the Estimates, the Claude Code behaviour doc) holds each dated observation of a platform or its docs as its one home, and the docs and code that draw a conclusion from it keep only that conclusion and a link to the line. An index that only copied observations kept in their sources drifted from them and gave two places to update; with the index as the home, the next reader checks one line, with its date and evidence, before relying on it.

A line records what was seen and nothing it is taken to mean: no conclusion, no cause, no "always", "never", "covers" or "can", and no open or withdrawn question. An edit-protection decision briefly rested on "an open-ended protection covers rows added later", a conclusion drawn from "the range reads back open-ended", and a follow-up probe overturned it. Had the line held only the reading, the conclusion would have stayed beside the decision that drew it, where the overturning probe would have reached it; a question still open lives in the doc that relies on it, or in an issue when a decision waits on it. A result seen again updates the line's date and evidence; a different result goes in above the old line, which stays, so a reversal is visible.

A `Documented:` line records what a platform's docs say, since a gate or a design sometimes rests on documented behaviour no probe has tested. It goes in only when a doc, an ADR or the code relies on it, so the index doesn't become a copy of the platform's docs.

This reverses the Codebase Priorities rule that a measurement stays in its source beside its conclusion and the Estimates only index it: a measurement's home is now the Estimates, and the source keeps its conclusion and a link to the line. A rule line whose rule is a number keeps the number.
