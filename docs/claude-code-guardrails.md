# Claude Code guardrails

Mechanics of the Claude Code hooks and project agent. Why they are shaped this way: [`docs/agent-behavior-design.md`](./agent-behavior-design.md).

Ten Node hooks in `.claude/hooks/`, registered in `.claude/settings.json`: five gate a call (the Bash-read guard, the pinned-target guard, the doc grant guard, the STYLE gate and the doc content gate) and five add feedback or a reminder. All fail open except where noted. Session state lives in `$TMPDIR/claude-guardrails/`.

**Start every session at the repo root.** The settings, hooks and agent load only from the root `.claude/`, so a session started inside `packages/*` runs with none of them and every call asks. Each package's `CLAUDE.md` says so; restart at the root.

## The hooks and the project agent

`.claude/settings.json` registers ten Node hooks in `.claude/hooks/`, TypeScript that `node` runs by stripping types (erasable syntax only, `.ts` imports, nothing from `packages/`), fail-open (bad input allows the call) unless noted, plus one project agent. `bashReadGuard.ts`, `pinnedTargetGuard.ts`, `styleGate.ts` and `docContentGate.ts` gate a call; the others add feedback or a reminder.

- **`bashReadGuard.ts`** (PreToolUse, Bash) denies a Bash read of `columnConfigs.ts`, unless it is a grep or a `sed -n` range of at most 150 lines. It also denies a whole-file dump (`cat`, unbounded `head`/`tail`, `sed` without `-n`, `sed -n '1,$p'`) of a repo file over 150 lines. The deny message names the alternative. Piped input, small files, anything under a `.probe/`, `dist/`, `coverage/` or `node_modules/` folder at any depth, and anything outside the repo are not guarded. The `columnConfigs.ts` it guards is every package's, found through the `generatedDir` in each `sheets.config.json` (`lib/sheetsConfigs.ts`). `lib/bashReads.ts` is tested beside it. The classifier (`lib/bashReads.ts`) is shared with `readCountNudge.ts`.
- **`pinnedTargetGuard.ts`** (PreToolUse, Bash and the gworkspace Sheets writes in `guardedSheetsWrites`, which a test keeps equal to the hook's matcher) keeps the dev standing yes pinned to the dev spreadsheet. It turns an allowed `dev:*` write (`dev:gen:configs`, `dev:chore … --send`, `dev:build`, `dev:push`, `dev:run`) into ask while a pin is off: the guard or its libs have uncommitted changes, or `packages/framework/sheets.config.json` names a spreadsheet other than the dev ID pinned in `lib/pinnedTargets.ts` (the config is gitignored, so git can't pin it). It allows a Sheets write only when `spreadsheet_id` is that pinned dev ID and every pin holds, and otherwise asks. An unreadable git state or config asks. A crash fails open on the Bash side, leaving the allow rule, and closed on the Sheets side, leaving the default ask. The decision is `lib/pinnedTargets.ts`, tested beside it. The isolation table it enforces: [`docs/how-it-runs.md`](./targets-and-gates.md#targets-dev-and-app).
- **`generatedEditWarning.ts`** (PreToolUse, Edit/Write) warns, without blocking, before an edit inside any package's `generatedDir`, naming that package's `*:gen:configs`: regenerate instead, floor entries included: fix the live tab or the seed ([`docs/generated-data.md`](../packages/framework/docs/generated-data.md)).
- **`agentsCostNudge.ts`** (PreToolUse, Edit/Write) reminds, without blocking, on the first edit to the root `AGENTS.md` in a session, once: every byte of that file loads on every turn, so add only what changes behavior on nearly every task ([`prose-files.md`](./agents/prose-files.md#what-an-addition-to-agentsmd-costs)). Nested `AGENTS.md` files draw nothing. The decision is `lib/agentsCostNudge.ts`, tested beside it.
- **`styleGate.ts`** (PostToolUse, Read and Bash; PreToolUse, Edit/Write) records a Read of `config/docs/code-style.md` that covers the whole file (no `offset` or `limit`, or bounds reaching its last line), or a Bash `cat` of it that no pipe trims (`BashReads.wholeFilePaths`), and denies an edit to a code file ESLint lints (any `.ts`, `.js` or `.mjs` outside `dist/`, `coverage/`, `node_modules/` and `.claude/worktrees/`) until that read is recorded for the session. **The gate set is the lint set minus each package's `generatedDir`**, whose files are left to `generatedEditWarning.ts`; it is `isInLintSet` in `lib/lintSet.ts`, shared with `lintFeedback.ts`. The gate reads only the general doc; the framework's rules are reached by the router and `packages/framework/src/AGENTS.md`. The decision is `lib/styleGate.ts`; both are tested beside them. Cursor spells the read event `postToolUse`; the hook accepts that spelling too, so a Cursor session records the same marker. The framework style doc is a separate Cursor gate ([`docs/cursor-guardrails.md`](./cursor-guardrails.md)).
- **`docGrantGuard.ts`** (UserPromptSubmit; PreToolUse, the gworkspace Doc writes in `grantedDocWrites`, which a test keeps equal to the hook's matcher) grants a spec's Deliverable its standing yes. A prompt that starts with `/implement-piece <n>` makes it read issue #n in `byronbroughten/writing` with `gh` and record the Doc IDs in its Deliverable section (a ticket's Shared rules), governed by the ticket's Parent spec, in `$TMPDIR/claude-guardrails/doc-grants.json`, keyed by Doc and not by session, so a cleanup agent inherits it. A Doc write to a recorded Doc is allowed while `gh issue view` says that issue is `OPEN`; a closed issue, an unreadable `gh` or any other Doc leaves the default ask. The deny from `docContentGate.ts` still wins over this allow. Only a user-typed prompt records a grant, but an agent that writes the JSON file through Bash could forge one. The decision is `lib/docGrants.ts`, tested beside it. Claude Code only.
- **`docContentGate.ts`** (PostToolUse, Read; PreToolUse, the gworkspace Doc writes in `gatedDocWrites`, which a test keeps equal to the hook's matcher) records a full Read of `docs/writing-style.md`, judged as `styleGate.ts` judges one (`isFullDocRead`), and denies a Doc write that puts text in until that read is recorded for the session. **Text** is `create_doc` with `content`, `modify_doc_text` with `text`, any `find_and_replace_doc` or `insert_doc_elements`, and `batch_update_doc` when an operation inserts or replaces text. Formatting-only writes pass: `update_paragraph_style`, `modify_doc_text` with formatting arguments only, and `batch_update_doc` with style operations only. The deny reason also names `docs/academic-writing-style.md` for academic work. The decision is `lib/docContentGate.ts`, tested beside it. Claude Code only; Cursor has no twin.
- **`lintFeedback.ts`** (PostToolUse, Edit/Write) runs after the Prettier step, in the same settings entry so the order holds: `eslint --fix` on the edited file under the package's own `eslint.config.mjs` (`--flag v10_config_lookup_from_file`), with `@typescript-eslint/no-unused-vars` off for that run so an import added one edit before its use isn't flagged, then Prettier again if the fix changed the file. It adds each error left, as `line:col rule message`, as context, and says nothing for a clean file. It lints only files in the lint set (`lib/lintSet.ts`), and fails open on a crash, a timeout (20 s) or output it can't parse. `npm run lint` stays the final gate. The feedback text is `lib/lintFeedback.ts`, tested beside it.
- **`readCountNudge.ts`** (PostToolUse on Read/Grep/Glob/Bash; reset on UserPromptSubmit) counts reads per turn: Read, Grep, Glob, and Bash calls the classifier calls reads. Edits, `tsc` and test runs are not counted. At 15 reads, and every 10 after, it reminds Claude to write findings down with `file:line`. Each subagent has its own count, and `repo-explorer` is exempt.
- **`contextNudge.ts`** (PostToolUse, every tool) reads the session's context size from its transcript: the last assistant message's `input_tokens` plus `cache_read_input_tokens` plus `cache_creation_input_tokens`. The first time it reaches the 150K ticket budget (`ticketBudgetTokens`, [`planning.md`](./agents/planning.md#ticket-size)) it reminds Claude, once per session and without blocking, to finish the step in hand and hand off per [`planning.md`](./agents/planning.md#handoffs). Subagents are skipped. The decision is `lib/contextNudge.ts`, tested beside it.
- **`.claude/agents/repo-explorer.md`** is a read-only (Read/Grep/Glob) Sonnet agent for sweeps of about 5+ files. It returns `file:line` plus verbatim quotes.

## Per-session state

Per-session state (the read log, whether config/docs/code-style.md and docs/writing-style.md were read, whether the AGENTS.md cost reminder fired, and whether the context nudge fired) lives in `$TMPDIR/claude-guardrails/`, keyed by session id.
