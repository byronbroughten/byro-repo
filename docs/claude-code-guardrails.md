# Claude Code guardrails

Mechanics of the Claude Code hooks and project agent. Why they are shaped this way: [`docs/agent-behavior-design.md`](./agent-behavior-design.md).

Eleven Node hooks in `.claude/hooks/`, registered in `.claude/settings.json`: five gate a call (the Bash-read guard, the tier gate, the branch guard, the STYLE gate and the doc content gate), five add feedback or a reminder, and one records state for a gate. All fail open except where noted. Session state lives in `$TMPDIR/claude-guardrails/`.

**Start every session at the primary root, or an issue workspace's root.** The settings, hooks and agent load only from a root's `.claude/`, so a session started inside `packages/*` runs with none of them. Each package's `CLAUDE.md` says so; restart at a root.

## The hooks and the project agent

`.claude/settings.json` registers eleven Node hooks in `.claude/hooks/`, TypeScript that `node` runs by stripping types (erasable syntax only, `.ts` imports, nothing from `packages/`), fail-open (bad input allows the call) unless noted, plus one project agent. `bashReadGuard.ts`, `tierGate.ts`, `branchGuard.ts`, `styleGate.ts` and `docContentGate.ts` gate a call; `branchRecord.ts` records what `branchGuard.ts` reads; the others add feedback or a reminder.

- **`bashReadGuard.ts`** (PreToolUse, Bash) denies a Bash read of `columnConfigs.ts`, unless it is a grep or a `sed -n` range of at most 150 lines. It also denies a whole-file dump (`cat`, unbounded `head`/`tail`, `sed` without `-n`, `sed -n '1,$p'`) of a repo file over 150 lines. The deny message names the alternative. Piped input, small files, anything under a `.probe/`, `dist/`, `coverage/` or `node_modules/` folder at any depth, and anything outside the repo are not guarded. The `columnConfigs.ts` it guards is every package's, found through the `generatedDir` in each `sheets.config.json` (`lib/sheetsConfigs.ts`). `lib/bashReads.ts` is tested beside it. The classifier (`lib/bashReads.ts`) is shared with `readCountNudge.ts`.
- **`tierGate.ts`** (PreToolUse, Bash and the gworkspace write and create tools; PostToolUse, Bash) applies the tier gate. On Bash it allows a commit, `npm run wrap-up`, `app:build` and the deploy aliases, asks for a raw push, `npm publish` and a bare `clasp` or `sheets-framework`, and allows an `app:chore <name> -- --send` only after this session dry-ran that chore, which PostToolUse records. On gworkspace it allows creating, copying, importing and exporting a file, allows a Sheets or Docs write (or a non-sharing `update_drive_file`) on a file one of the developer's two Google accounts owns, and asks for one on anyone else's, naming the file and owner. The sharing tools, and an `update_drive_file` that changes sharing, always ask, naming who and at what permission. The owner comes from Drive's `owners` field, read with the gworkspace server's stored token for the agent account (`lib/driveOwners.ts`) and cached per session; a failed lookup asks. The decisions are `lib/tiers.ts` and `lib/driveTiers.ts`, tested beside them.
- **`branchGuard.ts`** (PreToolUse, Bash) keeps a primary checkout (the root or a clone under `packages/`) on its branch. Its `mode` is strict: it denies every branch move (`git checkout <branch|sha>`, `checkout -b`, `switch`, `switch -c`) in a primary checkout. The interim form it replaced, still in `lib/branchGuard.ts`, left branch moves alone and denied only a `git commit` once HEAD's commit or branch changed since this session recorded it. File restores (`checkout -- <path>`, `checkout <ref> [--] <path>`, or a lone operand naming an existing path) always pass, `git -C` and `cd … &&` resolve the checkout acted on, and a target in an issue workspace or under `.claude/worktrees/` is never denied. Subshells (`(cd x && …)`), `pushd`, `--git-dir` and `--work-tree` are not resolved: the guard catches accidents, not evasion. After its own HEAD-moving git command, a session's record is re-recorded before its next decision. Each deny names the way through: the issue workspace, or a fresh session once the other one is done. The decision is `lib/branchGuard.ts`, tested beside it; the I/O is `lib/branchRecords.ts`.
- **`branchRecord.ts`** (SessionStart, SessionEnd) records each primary checkout's branch and HEAD at the start of a session started at the primary root, keeping a live record across a compact, and marks it ended at the end, so a resumed session starts a fresh record. A record with no end, written under a day ago, is live.
- **`generatedEditWarning.ts`** (PreToolUse, Edit/Write) warns, without blocking, before an edit inside any package's `generatedDir`, naming that package's `*:gen:configs`: regenerate instead, floor entries included: fix the live tab or the seed ([`docs/generated-data.md`](../packages/framework/docs/generated-data.md)).
- **`agentsCostNudge.ts`** (PreToolUse, Edit/Write) reminds, without blocking, on the first edit to the root `AGENTS.md` in a session, once: every byte of that file loads on every turn, so add only what changes behavior on nearly every task ([`prose-files.md`](./agents/prose-files.md#what-an-addition-to-agentsmd-costs)). Nested `AGENTS.md` files draw nothing. The decision is `lib/agentsCostNudge.ts`, tested beside it.
- **`styleGate.ts`** (PostToolUse, Read and Bash; PreToolUse, Edit/Write) records a Read of `config/docs/code-style.md` that covers the whole file (no `offset` or `limit`, or bounds reaching its last line), or a Bash `cat` of it that no pipe trims (`BashReads.wholeFilePaths`), and denies an edit to a code file ESLint lints (any `.ts`, `.js` or `.mjs` outside `dist/`, `coverage/`, `node_modules/` and `.claude/worktrees/`) until that read is recorded for the session. **The gate set is the lint set minus each package's `generatedDir`**, whose files are left to `generatedEditWarning.ts`; it is `isInLintSet` in `lib/lintSet.ts`, shared with `lintFeedback.ts`. The gate reads only the general doc; the framework's rules are reached by the router and `packages/framework/src/AGENTS.md`. The decision is `lib/styleGate.ts`; both are tested beside them. Cursor spells the read event `postToolUse`; the hook accepts that spelling too, so a Cursor session records the same marker. The framework style doc is a separate Cursor gate ([`docs/cursor-guardrails.md`](./cursor-guardrails.md)).
- **`docContentGate.ts`** (PostToolUse, Read; PreToolUse, the gworkspace Doc writes in `gatedDocWrites`, which a test keeps equal to the hook's matcher) records a full Read of `docs/writing-style.md`, judged as `styleGate.ts` judges one (`isFullDocRead`), and denies a Doc write that puts text in until that read is recorded for the session. **Text** is `create_doc` with `content`, `modify_doc_text` with `text`, any `find_and_replace_doc` or `insert_doc_elements`, and `batch_update_doc` when an operation inserts or replaces text. Formatting-only writes pass: `update_paragraph_style`, `modify_doc_text` with formatting arguments only, and `batch_update_doc` with style operations only. The deny reason also names `docs/academic-writing-style.md` for academic work. The decision is `lib/docContentGate.ts`, tested beside it. Claude Code only; Cursor has no twin.
- **`lintFeedback.ts`** (PostToolUse, Edit/Write) runs after the Prettier step, in the same settings entry so the order holds: `eslint --fix` on the edited file under the package's own `eslint.config.mjs` (`--flag v10_config_lookup_from_file`), with `@typescript-eslint/no-unused-vars` off for that run so an import added one edit before its use isn't flagged, then Prettier again if the fix changed the file. It adds each error left, as `line:col rule message`, as context, and says nothing for a clean file. It lints only files in the lint set (`lib/lintSet.ts`), and fails open on a crash, a timeout (20 s) or output it can't parse. `npm run lint` stays the final gate. The feedback text is `lib/lintFeedback.ts`, tested beside it. A file written through Bash skips this hook, the Prettier step and `styleGate.ts`; the git pre-commit hook (`.githooks/pre-commit`, wired by `npm install`) then checks Prettier and ESLint on the staged files.
- **`readCountNudge.ts`** (PostToolUse on Read/Grep/Glob/Bash; reset on UserPromptSubmit) counts reads per turn: Read, Grep, Glob, and Bash calls the classifier calls reads. Edits, `tsc` and test runs are not counted. At 15 reads, and every 10 after, it reminds Claude to write findings down with `file:line`. Each subagent has its own count, and `repo-explorer` is exempt.
- **`contextNudge.ts`** (PostToolUse, every tool) reads the session's peak context from its transcript through the runner's context meter (`runner/src/contextMeter.ts`). It resolves the meter as `@byronbroughten/spec-runner`, so a checkout needs `npm install` first; without it the hook fails open. The first time it reaches the ticket budget ([`planning.md`](./agents/planning.md#ticket-size)) it reminds Claude, once per session and without blocking, to finish the step in hand and hand off per the handoff doc. It reads the budget and the handoff doc's path (`ticketBudget`, `handoffDocPath`) through the runner's `runKnobsOrDefaults()` from `scripts/runner/runner.config.json`, falling back to the runner's defaults if that can't load. Subagents are skipped. The decision is `lib/contextNudge.ts`, tested beside it.
- **`.claude/agents/repo-explorer.md`** is a read-only (Read/Grep/Glob) Sonnet agent for sweeps of about 5+ files. It returns `file:line` plus verbatim quotes.

## Seeing what a hook sees

Never edit a hook to record what it sees; auto mode blocks it, and rightly. `npm run session:probe -- <folder>` starts a one-turn headless session there with its own SessionStart hook added through `--settings`, and prints `$CLAUDE_PROJECT_DIR`, the hook's cwd and its input. For anything else a hook can see, extend `runner/src/SessionProbe.ts`.

## Per-session state

Per-session state (the branch record, the read log, whether config/docs/code-style.md and docs/writing-style.md were read, whether the AGENTS.md cost reminder fired, and whether the context nudge fired) lives in `$TMPDIR/claude-guardrails/`, keyed by session id.
