# Agent-behavior design

Why the agent tooling around this repo is shaped the way it is: the hooks, gates, delegation rules and helper commands that decide how agents work here. [docs/design.md](../packages/framework/docs/design.md) holds the arguments for the codebase itself; this file holds the arguments for how agents work on it. The mechanics live in [`docs/claude-code-guardrails.md`](./claude-code-guardrails.md) and the rules in [AGENTS.md](../AGENTS.md) and [`docs/agents/`](./agents/).

## Adding a principle

Decisions are ADRs in [`docs/adr/`](./adr/). A principle may rest on one ADR from this repo, and earns its heading only by deciding cases its ADRs don't name; it gets an argument and instances only for what no single ADR holds, the argument across several ADRs or a citable case beyond its one ADR, and otherwise its heading links its ADR directly ([ADR 0020](./adr/0020-a-principle-may-rest-on-one-adr-and-a-reasoning-file-holds-only-what-no-adr-holds.md)). A new ADR making a principle's argument is added to it as a link plus one clause. A new principle is proposed to the developer and added only once approved.

## Principles

### Block narrowly, and name the way through; nudge everything else

A block that starves the agent of information costs more than it saves: the agent retries, works around it, or stalls. So a hard block is kept for a pattern that is both narrow and never right, and its message names the route that is allowed. Anything that is only usually wrong gets a reminder instead. Every guard fails open, so a bug in a hook can't stop unrelated work.

_Instances:_ [ADR 0011](./adr/0011-hard-block-only-narrow-patterns-and-nudge-the-rest.md) hard-blocks only two read patterns, each naming its alternative, and leaves the read count and size warnings as reminders that never stop a turn. An edit inside the generated folder is usually wrong but not never, since the config-sheet floor is hand-edited, so it draws a warning rather than a block (#71). [ADR 0012](./adr/0012-replace-agents-md-size-caps-with-a-stated-cost-of-adding.md) meets the first edit to the root AGENTS.md with a cost reminder rather than a cap or a block, since growing the file is sometimes right. [ADR 0018](./adr/0018-a-code-edit-is-denied-until-the-style-doc-is-read-in-full.md) denies a code edit only until the style doc is read in full, and its refusal names that read as the way through. [ADR 0013](./adr/0013-every-edit-happens-in-a-workspace-never-a-primary-checkout.md) has the primary-edit guard deny only an edit or commit in a primary checkout, with `issue:start` named as the way through. [ADR 0009](./adr/0009-runner-steps-get-refusals-not-prompts.md) gives a runner step's refusal a reason that names its way through, recording a blocker, rather than leaving the step to stall.

### Gate by what it costs to undo

Whether an action needs the developer's yes follows from one question: what would undoing it cost? The tiers that answer it, and which action sits in which, are in [`docs/targets-and-gates.md`](./targets-and-gates.md#the-tiers).

A runner step's ask is refused rather than prompted because nobody is there to answer, and a stalled run has cost more than any action an agent has taken.

The gates are designed against a fallible agent: one that means well and makes a mistake. [ADR 0007](./adr/0007-keep-untrusted-text-out-of-instructions-and-defer-containment.md) keeps Untrusted text out of agents' instructions, and hardening against the agent itself waits for its [containment triggers](./adr/0007-keep-untrusted-text-out-of-instructions-and-defer-containment.md#consequences), so no such gate is built ahead of them.

Quality checks and cost guards are not gates, and the tiers leave them alone: lint feedback, the style gate, the formatter, the read guards and the generated-file read deny.

_Instances:_ [ADR 0008](./adr/0008-gate-agent-actions-by-what-they-cost-to-undo.md) replaces rule-by-rule asks with one tier decision by what an action costs to undo. [ADR 0009](./adr/0009-runner-steps-get-refusals-not-prompts.md) turns a runner step's ask into a refusal, since nobody is there to answer and a stalled run costs more. [ADR 0010](./adr/0010-wrap-up-keeps-a-standing-yes-to-push-behind-a-secret-scan.md) keeps the one standing yes to push, wrap-up's, behind a scan for token shapes, the mistake no undo fixes, session landings included. A plain `issue:remove` is free because it refuses unlanded work, while `issue:remove --force` asks, since the work it discards can't be brought back (#257).

### Keep the payload on disk and the summary in context

Whatever enters the context is paid for on every later turn. A full payload, printed once, rides along through unrelated work. Show a summary that is enough to decide the next step, and keep the complete record somewhere a ranged read can reach it, so the summary never hides needed detail.

_Instances:_ a chore dry run prints one rendered line per request, and `-- --json` is the escape hatch for when a line looks wrong (the framework's `docs/how-it-runs/chore-dry-run.md`). [ADR 0015](./adr/0015-the-sheets-probe-prints-a-summary-and-keeps-the-full-response-on-disk.md) has the Sheets probe print keys, counts and sheet titles, and write the full response to disk for a ranged `Read`. [ADR 0016](./adr/0016-dispatched-agents-locate-and-quote-while-diagnosis-and-gates-stay-in-the-main-session.md) sends a sweep's reading to a dispatched agent, so only its quotes enter the main session's context. [ADR 0017](./adr/0017-a-rules-file-holds-only-the-rule-with-its-reasoning-one-pointer-away.md) keeps a rules file to its rule lines, so a rule's reasoning is paid only by a turn that follows the pointer to it.

### Approval covers what was named, and nothing next to it

_Instances:_ [ADR 0008](./adr/0008-gate-agent-actions-by-what-they-cost-to-undo.md) makes a share ask on its own, naming who gets access and at what permission, even on a file whose writes are free. [ADR 0005](./adr/0005-approve-an-issue-body-by-its-exact-text.md) ties an issue body's approval to its exact text, so any later edit falls outside it.

### Put each rule where it gets followed, and its reasoning one pointer away

What an agent loads without asking is paid for on every task, and a rule it has to go looking for is a rule it skips. So a behavior-changing rule is placed wherever it gets followed, even at the cost of repeating it, and the reasoning, examples and history are never auto-loaded: they sit exactly one pointer from the rule, behind the fixed sentence "Open a reasoning file only when you're changing the rule, or the rule's line doesn't decide your case". A rule goes on the highest rung it can reach: lint, then path-triggered (a nested `AGENTS.md`, a hook), then a router pointer, then prose. Lint needs no reader at all, and a path trigger reaches only the agents touching that folder. Hooks only reinforce, and no rule lives only in a hook, because more than one agent works this repo. A nested `AGENTS.md` is what Codex and Cursor read, and it is paired with a one-line `CLAUDE.md` importing it because Claude Code, with a root `CLAUDE.md` present, loads a subfolder's `CLAUDE.md` on demand but not its `AGENTS.md`. README.md is derived prose for people, so the facts agents need live in their homes and README mirrors them. A read-first gate denies rather than injects, so a doc already in context is never paid for twice.

A rules file holds only the rule: a rule line is the bolded rule plus at most a clause of scope or its one exception, and every example, instance, citation and why sits in the reasoning file. Brevity and clarity are held together by the written convention and by review instead, because a number can measure only one of them. A numeric cap became a target, rules padded or squeezed to fit it, so the size caps on AGENTS.md files went too: [ADR 0012](./adr/0012-replace-agents-md-size-caps-with-a-stated-cost-of-adding.md) replaced them with a stated cost, which is that every byte is paid on every turn and dilutes the rest, so the agent adding to the file weighs that itself ([`prose-files.md`](./agents/prose-files.md#what-an-addition-to-agentsmd-costs)). A lead is capped in bytes as well as lines, since a line count lets one long paragraph through, and a doc over 4 KB needs `##` headings, since a doc with none is one long lead read whole.

_Instances:_ [ADR 0017](./adr/0017-a-rules-file-holds-only-the-rule-with-its-reasoning-one-pointer-away.md) gives every rules file rule-only lines with the examples and reasoning in a folder one pointer away, the shape the style doc and packages/framework/docs/vocabulary.md now hold, and drops the rule-line cap for that written convention; [ADR 0019](./adr/0019-place-each-rule-on-the-highest-enforcement-rung-with-agents-md-the-only-router.md) puts each rule on the highest rung it reaches, so `src/`-only rules left the root AGENTS.md for `src/AGENTS.md`, the tier rule and the doc link and pairing checks moved to `npm run lint`, and README stopped routing agents; [ADR 0018](./adr/0018-a-code-edit-is-denied-until-the-style-doc-is-read-in-full.md) denies a code edit until the style doc is read in full, catching the most common miss without injecting the file; [ADR 0012](./adr/0012-replace-agents-md-size-caps-with-a-stated-cost-of-adding.md) replaces the AGENTS.md size caps with a stated cost of adding, since a cap became a target; [ADR 0014](./adr/0014-prose-gets-its-own-smell-baseline-in-a-gated-rules-file.md) gives developer-facing prose the code style doc's shape and gate, with its own smell baseline.
