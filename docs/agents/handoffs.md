# Handoffs

Write a handoff when a diagnosis finishes in a session near the ticket budget, or one that got a read-count nudge, and do it before implementing. It holds the conclusion, the files and line ranges the next step opens (only those, not every range the ticket touches), and the hypotheses already ruled out. A session that got a context nudge writes one once the step in hand is done, adding the changed files and what still fails if the code is red, and leaves the work uncommitted. When less than half the ticket is done and [the ticket split test](./tickets.md#the-ticket-split-test) says the rest is more than one ticket, it also proposes a split of the rest, a rough list of the remaining slices, each with what it delivers and its file count, for the developer to split the ticket before the next session. It ends with the `session: <id>` line from your context, which wrap-up reads. Post it as a comment on the issue, or save it as a file if there is no issue, then recommend a fresh session. A small diagnosis in a lean session needs no handoff.
