# @byronbroughten/spec-runner

Runs a spec's tickets through implement, review, finding triage, fix, checks and wrap-up, one agent step at a time, and leaves the developer a review list. It imports nothing from the repo around it: everything repo-specific is injected config, so it can be split out later. Its words are in [`GLOSSARY.md`](./GLOSSARY.md).

| Export | What it is |
| --- | --- |
| `@byronbroughten/spec-runner/AgentStep` | `AgentStep`: the port that launches one headless `claude -p` step as a cswap account and returns its `StepResult`: the schema-checked record or schema failure, session id, config folder, transcript path, peak context, exit subtype, latest usage reading and any limit hit. |
| `@byronbroughten/spec-runner/ClaudeAgentStep` | The real adapter: runs `cswap run <account> -- -p …` in `acceptEdits` and reads its stream-json, optionally logging it raw. |
| `@byronbroughten/spec-runner/FakeAgentStep` | The adapter run-loop tests script with `StepResult`s, or with functions of the request that act first, such as committing in its cwd. |
| `@byronbroughten/spec-runner/FakeNotices` | The notice port run-loop tests read back. |
| `@byronbroughten/spec-runner/GhCli` | The real `gh` port: the run loop reads issues, sub-issues and open blockers and comments through it, and the wrap-up closes issues and reads parents and comments. |
| `@byronbroughten/spec-runner/implementStep` | The implement step: `implementPrompt()`, a non-interactive fork of the vendored `/implement` that works in the issue workspace, never asks, commits once per changed repo and returns the implement record, carrying the latest handoff to a fresh step; `handoffOnlyPrompt` for a step resumed past the live ceiling; `implementRecordSchema` and the `ImplementRecord` type; and `implementRecordProblems()`, which refuses a record whose status disagrees with whether the step made a new commit (a handoff with a commit among them). The fork is recorded under `implement`'s `derivedInto` in byro-repo's `.claude/skills/upstream.json`. |
| `@byronbroughten/spec-runner/IssueWorkspaces` | The workspace module: `create()` builds an issue workspace (a root worktree outside the primary root with a worktree of each package clone inside, the issue's repo and any named extras on the issue branch, the rest detached at master), or returns the existing one; `promote()` puts a detached repo onto the issue branch partway through a ticket, `resume()` re-detaches the clean detached repos at the primary's current master and fails naming any with uncommitted changes or commits on no branch, and `list()` and `remove()` read and clear workspaces (`remove()` refuses the same unsaved work without force). Clone paths, the workspace folder, the shared gitignored files, the installer and the title lookup are injected. byro-repo's values are in `scripts/runner/runnerConfig.ts`, behind `npm run issue:list`, `npm run issue:promote -- <repo> <n> <repo-to-promote>` (the command the implement-step prompt names) and `npm run issue:remove -- <repo> <n> [--force]`. |
| `@byronbroughten/spec-runner/modelFit` | `pairOf()` reads a ticket body's `## Model fit` section, which must be last: a pair line naming one of the five pairs, then a reason. `pairLabelOf()` writes a pair as `Opus high`. |
| `@byronbroughten/spec-runner/Notices` | The notice port: one phone notification per run event, carrying only the spec title, a one-line summary and a link. |
| `@byronbroughten/spec-runner/NtfyNotices` | The plain ntfy adapter: posts the summary to a topic, with the spec title as its title and the link as its click target. The topic is a long random string from gitignored local config, byro-repo's in `scripts/runner/runner.local.json`. |
| `@byronbroughten/spec-runner/reviewStep` | The review step: `reviewPrompt()` runs the configured review skill on both axes against master and changes nothing; `reviewRecordSchema` and the `ReviewRecord` type, its findings as prose strings. |
| `@byronbroughten/spec-runner/runKnobs` | Every knob a run reads, typed and defaulted in `defaultRunKnobs`: repo map, account, skill names, check and auth-check commands, allowed-tools lists, turn caps, ticket budget and handoff doc. `loadRunKnobs()` lays a repo's JSON override file over them; `runKnobsOr()` falls back to the defaults when it can't, for a hook that fails open. byro-repo's override file is `scripts/runner/runner.config.json`. |
| `@byronbroughten/spec-runner/LandingLock` | The landing lock: a file per primary checkout holding pid, host and start time, taken over only when that pid is dead on this host, and polled while it is live. |
| `@byronbroughten/spec-runner/SessionProbe` | `SessionProbe`: starts a one-turn, no-tools headless session in a folder with a SessionStart hook added through `--settings`, and returns what that hook saw: `$CLAUDE_PROJECT_DIR`, its cwd and its stdin JSON. Nothing in the folder is edited. Behind `npm run session:probe -- <folder>`. |
| `@byronbroughten/spec-runner/SpecRun` | The run loop: `SpecRun.init(config).run(spec)` takes injected AgentStep, GitHub, notice and clock ports. It refuses a run whose open `ready-for-agent` tickets lack a valid Model fit (a ticketless spec runs as its own ticket), Stops on a failed auth check, a missing primary clone or one off master, or a red master, then runs the frontier ticket of the blocking graph, tie-broken by sub-issue order, through implement, review, checks and wrap-up in its issue workspace, re-reading labels and pairs before each launch. It never closes a split spec. Each outcome a later ticket will handle is an `UnhandledStop`: the ticket stays unlanded, the spec gets a comment and the run ends with one notice. The per-spec run state, progress log and raw step logs live in the state folder, so a rerun resumes at the step reached. byro-repo's values are in `scripts/runner/runnerConfig.ts`, behind `npm run runner -- <owner/repo> <n>`. |
| `@byronbroughten/spec-runner/UnhandledStop` | The outcomes the run loop doesn't handle yet (review findings, red checks, a step error, a blocker, a schema failure, a handoff, a wrap-up failure, a workspace that can't resume, a Model fit edited invalid), and the error carrying one with its detail and log path. |
| `@byronbroughten/spec-runner/WrapUp` | The wrap-up script: `WrapUp.init(config).run(issue)` lands a ticket with no agent from its facts file. It builds and checks the merge commits in the issue workspace, records the outcome row, fast-forwards each primary's master under the landing lock and pushes, deletes the branches, removes the workspace, closes the issue and checks the parent, merging the facts `transcriptFacts` computes over the passed ones, stopping at the first failure and recording finished steps so a rerun skips them. byro-repo's values are in `scripts/runner/runnerConfig.ts`, behind `npm run wrap-up -- <repo> <n>`. |
| `@byronbroughten/spec-runner/WrapUpFailure` | The typed failure a wrap-up stops on: conflict, red checks, dirty tree, foreign branch, failed parent check or network. |
| `@byronbroughten/spec-runner/contextMeter` | `ContextMeter`: a session's peak context, the most input + cache-read + cache-creation tokens any one main-loop assistant message carried. Feed it stream-json events with `observe()` and read `peak`, or pass a whole transcript to `ContextMeter.ofTranscript()`. |
| `@byronbroughten/spec-runner/limitGuard` | The limit guard: `readCswapList()` turns `cswap list --json` into per-account readings (a missing one is `undefined`, never thrown), and `decideStep()` picks launch, change account, Limit wait or Stop from them, the pinned account and the day's account changes, with `defaultLimitGuardKnobs` for its thresholds, margin and soft cap. |
| `@byronbroughten/spec-runner/outcomeLog` | The outcome log's file layout: a ticket's path under its spec's folder, its one-row table with `unrecorded` for facts nobody computed, and the commit message. |
| `@byronbroughten/spec-runner/transcriptFacts` | `transcriptFactsOf()`: the outcome facts computed from transcripts, found by the session ids and account config folder the runner records plus the handoff comments' `session: <id>` lines: pair, each implementer session's peak context, duration, API-equivalent cost (implementer, its subagents and any fixer) and triage cost, from the per-model price table `modelPrices`. `limitUsedOf()` writes Limit used from before and after readings. A fact with a missing transcript or reading stays `unrecorded`. |

## Tests

Vitest, in the root's `tooling` project: `npm test` from the repo root, or `npx vitest run runner` for just these. `npm run tsc` and `npm run lint` from the root reach it too.
